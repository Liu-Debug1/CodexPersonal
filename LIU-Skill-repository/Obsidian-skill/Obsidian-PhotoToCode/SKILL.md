# Obsidian-PhotoToCode

## 概述

将 Obsidian 笔记中的代码截图通过 OCR 提取为本地代码块，便于检索、复制和后续编辑。OCR 失败时根据上下文推断。只替换代码截图，保留流程/架构/示意图。

## 触发条件

- 用户要求「整理笔记」「优化笔记」「整理格式」时，**自动执行**
- 不要求用户单独开口，作为笔记整理流程的一环

## 工作流程

### 1. 扫描图片

读取目标 `.md` 文件，收集所有 `![描述|尺寸](url)` 格式的图片引用。

### 2. 判断图片类型

| 判断依据 | → 处理方式 |
|:---------|:----------|
| 图片前后文字描述的是「代码」「函数」「变量」「错误示范」等 | → 认定为代码截图 |
| 图片 alt 文本含「结构」「流程」「示意图」「对比」「区别」等 | → 认定为图示，保留 |
| 图片 alt 文本含「代码」「示例」「解决」「错误」「正确」等 | → 认定为代码截图 |

### 3. OCR 提取（优先）

优先使用 OCR 真实提取图片中的代码文字，而非凭空推断。

```powershell
# 使用辅助脚本
powershell -File ".claude/skills/Obsidian-PhotoToCode/ocr_helper.ps1" -ImagePath "图片/xxx.png"
```

成功返回格式：`{"source":"ocr_space","text":"提取的代码..."}`
失败时降级到下一步。

### 4. 上下文推断（OCR 失败时备用）

仅在 OCR 不可用时，根据图片周围的文字上下文和 alt 描述，还原合理的 C/C++ 代码块：

- 使用 ` ```c ` 或 ` ```cpp ` 代码块
- 代码内容要匹配上下文描述的逻辑
- 如果文字中已有「正确/错误」的区分，生成两个对比代码块
- 如果公式/规则已用文字描述清楚，代码块可以是简洁的示例

### 5. 删除图片引用

确认代码块已写入后，删除原 `![[xxx.png]]` 或 `![xxx](url)` 引用。

### 6. 保留图示

流程图、架构图、生命周期图等**不做任何修改**。

## 输出格式

```markdown
原来：
> 文字描述...
> ![代码截图|400](url)

改为：
> 文字描述...
> ```c
> // 根据上下文推断的代码
> void func(void) {
>     ...
> }
> ```
```

## 注意事项

- 无法直接读取图片时，**根据上下文文字描述推断代码内容**
- 不确定是代码还是图示时 → 保留原图，不删
- 代码块尽量简洁，不编造上下文没有提到的逻辑
- 不改变图片 alt 描述中已有的文字信息
