# Obsidian

将 Obsidian 任务分为两层：

1. Vault 层：搜索、创建、移动、删除、重命名笔记。
2. 内容层：在不破坏用户既有结构的前提下整理笔记，提高长期复习和工程复用效率。

## Vault 操作

### 操作优先级

1. 搜索和定位：优先 `obsidian-cli search` 或 `obsidian-cli search-content`。
2. 创建、移动、重命名、删除：优先 `obsidian-cli`，以维护常见链接。
3. 纯内容编辑：直接修改 `.md` 文件。

### 约束

- 不猜测 Vault 路径；优先使用 `obsidian-cli print-default --path-only` 或现有上下文确认。
- 不主动修改 `.obsidian/` 配置目录，除非用户明确要求。
- 批量整理先确认影响范围，再统一执行。
- 移动或重命名笔记优先使用 `obsidian-cli move`。

## 内容整理原则

- 目标是清晰、可检索、可复习和可复用，不是制造花哨排版。
- 结论先行，后续补充原因、实现、示例、边界或关联场景；不要机械套用固定章节。
- 保留可读的自然段、过渡句和连续推理，不把所有内容强行列表化。
- 保留并正确处理 wikilink、embed、frontmatter、表格、代码块、Callout、ASCII 框图和 Mermaid。
- 发现新增内容与既有笔记主题重复时，将有价值的新内容合并进已有笔记的对应位置；不要创建平行的重复笔记。

## 标题与层级

### 默认行为

- 保护用户已设置好的 `#` 至 `#####` 层级关系。
- 默认只在现有层级下整理内容；不主动升降级、重构或重新编号标题。
- 若笔记没有 H1，在 YAML frontmatter 后插入以文件名命名的 H1；没有 frontmatter 时插入到文件开头。此操作不得改变原有较低级标题的层级。

### 仅在用户明确要求时统一编号

只有用户明确要求“重构标题层级”“重新编号”或“统一标题体系”时，才重排或编号标题。使用以下五层格式：

| 层级 | 格式 | 例子 |
| --- | --- | --- |
| H1 | `一、标题` | `# 一、ROS 2 通信概览` |
| H2 | `1. 标题` | `## 1. 发布订阅` |
| H3 | `1.1 标题` | `### 1.1 节点与话题` |
| H4 | `1.1.1 标题` | `#### 1.1.1 消息类型` |
| H5 | `(1) 标题` | `##### (1) 队列深度` |

- 每个 H1 下的 H2 从 `1.` 重新开始；下级编号跟随所属父级。
- 每个 H4 下的 H5 从 `(1)` 重新开始。
- 不启用 Number Headings 的全局自动编号。它不能准确表达中文 H1 和括号 H5，且会改写既有编号。

## 元素选型与排版

### 连续内容与空行

- 编写、整理、优化或将图片内容转写为 Obsidian Markdown 时，不要为视觉留白无端插入空行。
- 同一逻辑内容块中的连续文字、同一列表项的说明、同一段落的补充解释，以及图片转写后逻辑连续的内容保持连续；除非 Markdown 结构要求，否则不在中间插入空白行。
- 仅在内容语义或 Markdown 结构确实切换时保留必要空行，例如不同标题区块、彼此独立的段落、代码块与正文、表格与非表格内容，以及 Callout 与普通正文之间。
- 图片转文本按原始内容的逻辑段落组织；不要将连续段落、一个列表项或一组连续步骤拆成多个由空行隔开的片段。
- 不删除用户原有且具有明确结构作用的空行；本规则只约束本次新增或改写的内容。

### 列表、表格和强调

- 并列知识点、步骤、命令或概念优先用列表组织。
- 当前最低层级标题下有多个并列操作或概念时，优先使用有序列表；序号先给出概括性动作或结论，再在其下放介绍、命令、参数、示例输出和注意事项。
- 多维度、可横向比较的信息使用 Markdown 表格；不要把有先后依赖的操作步骤强行转成表格。
- 单句结论、关键边界使用 `**粗体**`；重要且需要快速回看的信息可使用 `==高亮==`；术语、命令、路径、标识符使用行内代码。
- 风险、限制和易错点使用 `> [!warning]`；补充说明使用 `> [!NOTE]` 或更贴切的 Callout 类型。

### 代码、公式和图示

- 代码使用带语言标识的 fenced code block；高置信判断为代码的图片转写为相应语言的代码块并删除原图片引用。流程图、架构图和无法可靠识别的图片保留。
- 当说明句以“：”或明显引出命令、目录、输出的内容结尾时，下一行可直接接 fenced code block，不额外插入空行。
- 修复残留的 LaTeX 与纯文本公式拼贴：保留原公式语义，改为干净且可渲染的行内 `$...$` 或块级 `$$...$$` LaTeX；不要凭空改动符号含义。
- 结构、关系或数据流用文字加 ASCII 框图能更清楚表达时，优先使用 ASCII 框图；复杂且确有必要时再使用 Mermaid。

### 图片边界

- Vault 内本地附件使用 Obsidian 嵌入格式，例如 `![[图片/xxx.png|400]]`；实际附件目录以项目 AGENTS.md 为准。
- 外部 URL 图片使用 Markdown 图片语法并保留宽度标记，例如 `![示意图|400](https://example.com/image.png)`。
- 原理图通常使用 400-500 宽度，局部细节图通常使用 300 宽度；按图片可读性调整，不机械套用。
- 能以可检索的文字、列表或表格完整表达的信息，不用信息类截图替代。

## 推荐整理顺序

1. 通读笔记并确认是否已有合理标题层级和重复主题。
2. 仅在缺少 H1 时补齐文件名 H1；除非用户明确要求，否则不改既有标题层级或编号。
3. 合并重复内容，修正明显术语和拼写问题。
4. 根据内容选择列表、表格、代码块、Callout、强调和框图。
5. 修复公式、图片引用和代码图片，检查 Obsidian Markdown 渲染边界。

## 与其他 Skill 的分工

- `obsidian-markdown`：Obsidian Markdown 的语法细节，例如 wikilink、embed、Callout、frontmatter。
- `obsidian-cli`：CLI 的具体命令与可用能力。
- `obsidian-bases`：Bases 的表格、卡片、公式和过滤。
- `json-canvas`：`.canvas` 文件的节点和连线。

## 完成前自检

- 默认整理没有重排用户已有标题层级。
- 缺失 H1 时已在 frontmatter 后或文件开头补入文件名 H1。
- 只有明确要求统一编号时才应用五层编号规则。
- 列表、表格、Callout、公式、图片和代码块与信息类型匹配。
- 新增或改写内容中的同一逻辑块未被无语义空行拆散，结构切换处的必要空行仍保留。
- 没有破坏 wikilink、embed、frontmatter、代码块、表格和 Callout。
