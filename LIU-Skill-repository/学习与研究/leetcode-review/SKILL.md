# LeetCode C++ 复盘

## 目标

把每道题整理成可复用的解题经验、可直接提交的源码和可执行的 Anki 重做任务，而不是只保存一份能通过的代码。每次完整复盘同步维护算法结论、源码结构、调用示例、分类看板、刷题记录和 Anki 卡片。

## 固定位置

- 题解根目录：`D:\桌面\Ob_Learning\嵌入式\C&C++\Leetcode`
- 复盘看板：`D:\桌面\Ob_Learning\嵌入式\C&C++\Leetcode\Leetcode复盘看板.md`
- 刷题记录：`D:\桌面\Ob_Learning\嵌入式\C&C++\Leetcode\C++刷题.md`
- Anki 规则：`D:\桌面\Ob_Learning\嵌入式\C&C++\Leetcode\Anki刷题管理说明.md`
- C/C++ 代码规范：`D:\桌面\Ob_Learning\嵌入式\C&C++\代码规范.md`

开始复盘或更新看板前，完整读取 [复盘与看板规范](references/review-contract.md)。涉及源码编辑时，同时遵守当前仓库 `AGENTS.md` 和上述代码规范；规则冲突时以当前仓库 `AGENTS.md` 为准。

## 工作流

1. **锁定题目范围**
   - 优先使用本轮对话中的题目、用户贴出的代码和明确指定的 `.cpp` 文件。
   - 路径不明确时，在题解根目录按函数名或题目名搜索，不凭相似文件名猜测修改目标。
   - 默认一次只处理当前题目；用户明确要求批量整理时，才批量扫描和迁移源码。

2. **检查算法与边界**
   - 检查编译问题、核心逻辑、循环不变量、边界条件、未定义行为和复杂度。
   - 在最终复盘说明时间复杂度、额外空间复杂度，并解释复杂度符号含义；复杂度不写入看板索引表。
   - 用户明确要求修正或批量迁移时，修复已经确认的编译、警告、LeetCode 粘贴兼容性和明显逻辑问题；保留原有算法意图，不做无关重构。

3. **形成题目复盘**
   - 用通俗语言说明核心突破口，再给出标准流程、关键不变量、终止条件和适用边界。
   - 只记录本题真正涉及且可复用的 C++ 知识和 API，标准库类型与函数始终显式使用 `std::`。
   - 只提炼可以迁移到其他题目的结构，不把整道题换变量名冒充模板。

4. **统一源码结构**
   - 按固定顺序写入：头文件、带 API 注释的教学版 `Solution`、类后的注释调用示例、文件末尾的无注释完整 `Solution` 类。
   - API 注释至少说明功能、参数含义和有效范围、返回值。
   - 逻辑注释说明意图、不变量、边界或风险，不翻译显而易见的语句。
   - 调用示例只使用注释代码，展示输入、调用方式和预期结果，不引入默认会参与编译的 `main()`。
   - 纯净版使用块注释包裹，不保留任何注释；解除最外层块注释后应能直接复制到 LeetCode。
   - 纯净版必须从教学版实现直接复制，只删除注释，不另写算法；解除注释后单独编译验证。
   - 链表题的纯净 `Solution` 类使用 LeetCode 提供的全局 `ListNode`；本地测试定义放在类外，不嵌套到 `Solution` 中。
   - 禁止添加 `using namespace std;`。

5. **更新 Markdown 看板**
   - 看板只保留 `## 1.题目索引` 下的算法分类三级标题，例如 `### 1.1 哈希（Hash）`。
   - 每个分类使用独立三列表格：`题目`、`函数作用`、`源码位置`。
   - 函数作用单元格先写实际函数名，再用一句话直接说明作用；复杂度、算法套路和状态不放入表格。
   - 以源码相对路径作为唯一键，更新原行，不重复追加；确认 Wikilink 指向真实文件。
   - 不创建或同步 `.canvas` 副本，不恢复标签维护。

6. **记录刷题知识点**
   - 只对本次完整复盘的当前题目执行；不批量回填历史题目，也不改动历史 Anki 卡。
   - 在 `C++刷题.md` 中按 `##### (序号)算法分类: 题目名` 定位题目；存在时原地更新，不存在时在 `### 6.2 算法套路` 下按现有编号追加。
   - 标题下先写 Vault 相对 Wikilink 格式的源码位置，再写 `https://leetcode.com/problems/<slug>/` 官方链接。
   - 从用户围绕本题实际提出的问题中筛选最重要的 `0-2` 个知识点；每个知识点采用“问题 + 简洁答案 + 必要时最小示例”，不得为了凑数量新增泛泛知识。
   - 记录内容必须与本次创建的知识卡一致；没有知识卡时不创建空占位段落。

7. **创建 Anki 复习卡**
   - 创建前用 AnkiConnect 的 `version` 验证 `http://127.0.0.1:8765`；不可用时提示用户启动 Anki，不声明建卡成功。
   - 使用已存在的 `Leetcode刷题` 卡组和 `问答题` 模板；字段固定为 `正面`、`背面`。先调用 `deckNames`、`modelNames`、`modelFieldNames` 验证实际名称与字段。
   - 每题只维护 `1` 张源码重做卡：正面包含题号、题名、难度、分类、最小题面提示和 LeetCode 链接；背面包含本地源码 Wikilink、重做要求，以及源文件中的完整无注释可提交代码。代码使用 Anki 可渲染的 `<pre><code class="language-cpp">` 块，包含该实现所需头文件与无注释 `Solution`；LeetCode 题面提供的节点定义不重复写入。用户应先在本地独立重写，翻面后再核对代码。
   - 源码重做卡使用标签 `Leetcode`、分类名、`lc-<题号>`、`lc-source`。先以 `deck:Leetcode刷题 tag:lc-<题号> tag:lc-source` 查重；找到 `1` 张时调用 `updateNoteFields` 更新，找到多张时先用 `notesInfo` 报告重复项并停止，绝不自行删除。
   - 知识卡只从当前题目实际对话困惑中选择 `0-2` 张；标签为 `Leetcode`、分类名、`lc-<题号>`、`lc-knowledge`。先查询同题已有知识卡数量：已有 `2` 张时不再增加；已有 `0-1` 张时只新增到总数不超过 `2`。添加前调用 `notesInfo`，将候选问题与已有卡的 `正面` 字段逐字比较，已存在时跳过。
   - 创建前先判断卡片类型。若不依赖某个变量、表达式、循环顺序、容器 API 或本题状态更新即可回答，属于**纯概念卡**；正面可只保留固定题目信息和单个问题。若问题是“本题为什么这样保存/更新/比较”“这段代码为什么这样写”“某变量、循环或 API 为什么此处这样使用”，属于**代码推理卡**；不能只给题目链接后直接提问，因为复习者不应先凭记忆还原整段实现。
   - 每张知识卡只解决一个用户真实困惑。正面必须先固定写明题号、题名、难度、分类和可点击的 LeetCode 官方链接。代码推理卡随后依次写入：源文件相对题解根目录的位置（例如 `<code>PrefixSum/example.cpp</code>`）、`<pre><code class="language-cpp">` 包裹的最小相关 C++ 片段、单个问题。片段从同一题的无注释可提交实现中精确节选，至少保留提问涉及的变量或容器、关键更新或查询、必要的循环/条件上下文；省略无关代码可以，但不使用伪代码、`...` 或会直接解释答案的注释。背面给结论、原因与必要的最小示例。
   - 题号、题名、难度、分类或官方链接任一项缺失或与当前题目不一致时，视为知识卡字段不完整：对尚未创建的候选卡补全后再创建；对本次完整复盘查重到的同题知识卡，先调用 `notesInfo` 核对字段，再用 `updateNoteFields` 仅补全或修正题目上下文，保留其原有知识问题与背面内容。若已有代码推理卡缺源文件位置或代码片段，也只扩充其正面，不改写问题、背面、标签或调度。知识卡不因内容复盘而自动替换或删除，保护已开始的复习调度。
   - 默认只处理当前题目。用户明确要求“审查全部/历史 Anki 卡”时，才查询 `deck:Leetcode刷题 tag:lc-knowledge` 的全部卡片：逐题定位真实本地源码，按上述规则补齐代码推理卡，并报告已更新、纯概念跳过及无法定位源码的数量。
   - Anki 卡片创建或更新完成后，记录返回的 note ID、数量和跳过原因；不要把 AnkiConnect 当作 AnkiWeb 同步的替代品。

8. **完成验证**
   - 条件允许时使用 C++17、`-Wall -Wextra -Werror` 编译教学版和解除注释后的纯净版。
   - 对修改范围执行最小行为测试，覆盖普通输入、边界输入和题目中的关键反例。
   - 检查看板分类、三列表格、源码链接和题目数量，确认无重复或失效索引。
   - 验证 `C++刷题.md` 的题目标题、源码链接、官方链接和知识点与 Anki 知识卡一致；代码推理卡还应以 `notesInfo` 确认正面同时有真实源文件相对路径、`language-cpp` 代码块和问题，且本地源文件存在。
   - 最终回答先给结论，再说明复盘提炼、源码修改、看板更新、刷题记录、Anki 建卡与验证结果。

## 边界

- 不因目录分类不完善而批量搬迁无关旧文件；新增分类按需建立。
- 不覆盖用户未授权的无关改动；批量整理时只修改明确纳入范围的题解、看板和 Skill。
- 不把所有标准库函数都收录进复盘，只记录本题使用且具有复用价值的 API。
- Skill 不是后台 Hook；必须依据当前对话触发后执行，不能凭空判定题目已经完成。
- 用户仅讨论思路、语法或局部代码而未请求完整复盘时，不创建 Anki 卡，也不修改 `C++刷题.md`。
