# 复盘与看板规范

## 单题复盘结构

按当前问题复杂度选用必要部分，不为凑格式重复代码：

1. **正确性结论**：能否通过；若不能，先给最关键的失败原因。
2. **核心思路**：用通俗语言解释突破口和为什么成立。
3. **标准流程**：输入处理、核心循环或递归、终止条件、结果输出。
4. **关键不变量**：循环或数据结构在每一步必须保持什么成立。
5. **复杂度**：时间、额外空间，以及符号含义；只在复盘说明中记录，不写入看板表格。
6. **C++ 知识与 API**：只列本题使用且值得复用的内容，显式写 `std::`。
7. **易错点**：记录错误原因和下次可以自行识别的信号。
8. **可复用模板**：仅在结构可以迁移到其他题目时提供。

## 源码固定结构

每个题解 `.cpp` 按以下顺序组织：

1. 头文件。
2. 教学版 `Solution` 类：函数前有中文 API 注释，函数内部注释解释意图、不变量、边界或风险。
3. 类后的注释调用示例：展示输入、对象创建、函数调用和预期输出；示例不参与编译。
4. 文件末尾的无注释复制版：用一个外层块注释包住完整 `Solution` 类，解除外层注释后可直接复制到 LeetCode。

纯净版必须从教学版复制后只删除注释，不重新设计或修改算法。验证时将纯净版临时解除注释，和教学版分别编译。链表题的纯净类使用 LeetCode 的全局 `ListNode`，本地测试定义放在类外。

## 主分类

源码只放入一个最能代表本题核心矛盾的主分类：

`Array`、`String`、`Hash`、`LinkedList`、`StackQueue`、`Heap`、`Tree`、`Graph`、`BinarySearch`、`Backtracking`、`DynamicProgramming`、`Greedy`、`MathBit`、`SimulationDesign`

看板标题使用中文加英文，例如 `### 1.1 哈希（Hash）`；标题对应源码目录，新增分类时按当前编号顺序继续添加。

## 看板字段

看板在 `## 1.题目索引` 下按算法类型拆分三级标题。每个分类使用独立三列表格：

| 字段 | 填写规则 |
|---|---|
| 题目 | 使用 LeetCode 正式英文名或已确认中文名 |
| 函数作用 | 先写带 `()` 的实际函数名，再用一句话直接说明作用 |
| 源码位置 | 使用相对看板位置的 Obsidian Wikilink |

复杂度、算法套路和复盘状态只在复盘说明或源码注释中保留，不放入看板索引表。

## 幂等更新

1. 将源码相对路径视为唯一键。
2. 更新前先搜索该 Wikilink。
3. 找到时修改原行；找不到时按主分类和题目名插入对应分类表格。
4. 不根据函数名去重，因为不同题目可能使用相同函数名。
5. 保留看板中用户手写的其他章节与备注。
6. 完成后确认每个 Wikilink 指向真实文件，且每个源码只出现一次。

## Anki 与刷题记录

完成一次当前题目的完整复盘后，必须同步维护 `C++刷题.md` 和 Anki；只讨论思路或局部代码时不执行本节。

1. **刷题记录格式**
   - 用 `##### (序号)算法分类: 题目名` 作为唯一题目标题；通过已有题名或源码 Wikilink 查找并原地更新，不能重复追加。
   - 标题后依次记录：Vault 相对 Wikilink 源码位置、`https://leetcode.com/problems/<slug>/` 官方链接、`0-2` 条本题核心知识点。
   - 核心知识点只来自用户在本题对话中的真实困惑；每项保持“问题 + 简洁答案 + 必要时最小示例”。没有知识卡时不留空标题。

2. **源码重做卡**
   - 每题只维护一张，使用 `Leetcode`、分类名、`lc-<题号>`、`lc-source` 标签。
   - 正面给题号、题名、难度、分类、最小题面提示与官方链接；背面给本地源码 Wikilink、先独立重写的要求及完整无注释可提交代码。用 `<pre><code class="language-cpp">` 渲染代码，并包含所需头文件；题面提供的节点定义不重复写入。
   - 按 `deck:Leetcode刷题 tag:lc-<题号> tag:lc-source` 查询：没有则创建，恰有一张则更新字段，多于一张则报告并停止。

3. **核心知识卡**
   - 每题总数最多两张，使用 `Leetcode`、分类名、`lc-<题号>`、`lc-knowledge` 标签。
   - 先判断问题是否脱离具体实现也能回答。定义、复杂度通则等不依赖本题变量、控制流或 API 的为纯概念卡；正面固定先写题号、题名、难度、分类和可点击的 LeetCode 官方链接，再写一个真实困惑。问“为什么保存/更新此状态”“为什么本题这样比较”“这段循环/API 为什么这样用”等必须结合当前题源码才能回答的，为代码推理卡。
   - 代码推理卡的正面顺序固定为：题目元信息和官方链接、源文件相对题解根目录的位置、`<pre><code class="language-cpp">` 关键片段、一个真实问题。关键片段从无注释可提交 `Solution` 中精确截取，覆盖被问变量或容器、关键读写/更新、必要的循环或条件边界；不以 `...` 伪代码替代缺失逻辑，也不放会直接回答问题的解释性注释。这样复习者可以推理“为什么”，而不是先背回整份代码。
   - 先查询本题已有数量；到达两张即停止。添加前用 `notesInfo` 读取同题知识卡，并在比较前剥离固定题目上下文后，将候选问题与已有问题逐字比较；重复时跳过。对本次完整复盘查重到的同题知识卡，若题目元信息缺失，或代码推理卡缺源码位置/关键片段，使用 `updateNoteFields` 仅补齐正面上下文，保留原问题、背面、标签和复习调度。知识卡不因内容复盘而自动替换或删除。
   - 默认不批量修改历史卡；只有用户明确提出审查或迁移历史 Anki 卡时，才扫描 `deck:Leetcode刷题 tag:lc-knowledge`，逐题核实源文件后补齐代码推理卡，并报告无法定位源码的异常项。

4. **接口与字段验证**
   - 先对 `http://127.0.0.1:8765` 调用 `version`；失败即提示启动 Anki 并跳过建卡。
   - 调用 `deckNames`、`modelNames` 和 `modelFieldNames`，确认 `Leetcode刷题`、`问答题`、`正面`、`背面` 均存在后才调用 `addNote` 或 `updateNoteFields`。
   - 卡片操作结束后报告 note ID、创建/更新/跳过数量；代码推理卡还要报告源码存在性与正面代码块校验；不能把本地建卡等同于 AnkiWeb 同步。
