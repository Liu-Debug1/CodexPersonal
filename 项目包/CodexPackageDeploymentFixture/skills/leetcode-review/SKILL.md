# LeetCode C++ 复盘

## 目标

把每道题整理成可复用的解题经验和可直接提交的源码，而不是只保存一份能通过的代码。每次复盘同步维护算法结论、源码结构、调用示例和分类看板。

## 固定位置

- 题解根目录：`D:\桌面\Ob_Learning\嵌入式\C&C++\Leetcode`
- 复盘看板：`D:\桌面\Ob_Learning\嵌入式\C&C++\Leetcode\Leetcode复盘看板.md`
- C/C++ 代码规范：`D:\桌面\Ob_Learning\嵌入式\C&C++\代码规范.md`

开始复盘或更新看板前，完整读取 [复盘与看板规范](references/review-contract.md)。涉及源码编辑时，同时遵守当前仓库 `AGENTS.md` 和上述代码规范；规则冲突时以当前仓库 `AGENTS.md` 为准。

## 工作流

1. **锁定题目范围**
   - 优先使用本轮对话中的题目、用户贴出的代码和明确指定的 `.cpp` 文件。
   - 路径不明确时，在题解根目录按函数名或题目名搜索，不凭相似文件名猜测修改目标。
   - 默认一次只处理当前题目；用户明确要求批量整理时，才批量扫描和迁移源码。

2. **检查算法与边界**
   - 检查编译问题、核心逻辑、循环不变量、边界条件、未定义行为和复杂度。
   - 在最终复盘说明时间复杂度、额外空间复杂度，并解释复杂度符号含义；复杂度不写入看板索引表。
   - 用户明确要求修正或批量迁移时，修复已经确认的编译、警告、LeetCode 粘贴兼容性和明显逻辑问题；保留原有算法意图，不做无关重构。

3. **形成题目复盘**
   - 用通俗语言说明核心突破口，再给出标准流程、关键不变量、终止条件和适用边界。
   - 只记录本题真正涉及且可复用的 C++ 知识和 API，标准库类型与函数始终显式使用 `std::`。
   - 只提炼可以迁移到其他题目的结构，不把整道题换变量名冒充模板。

4. **统一源码结构**
   - 按固定顺序写入：头文件、带 API 注释的教学版 `Solution`、类后的注释调用示例、文件末尾的无注释完整 `Solution` 类。
   - API 注释至少说明功能、参数含义和有效范围、返回值。
   - 逻辑注释说明意图、不变量、边界或风险，不翻译显而易见的语句。
   - 调用示例只使用注释代码，展示输入、调用方式和预期结果，不引入默认会参与编译的 `main()`。
   - 纯净版使用块注释包裹，不保留任何注释；解除最外层块注释后应能直接复制到 LeetCode。
   - 纯净版必须从教学版实现直接复制，只删除注释，不另写算法；解除注释后单独编译验证。
   - 链表题的纯净 `Solution` 类使用 LeetCode 提供的全局 `ListNode`；本地测试定义放在类外，不嵌套到 `Solution` 中。
   - 禁止添加 `using namespace std;`。

5. **更新 Markdown 看板**
   - 看板只保留 `## 1.题目索引` 下的算法分类三级标题，例如 `### 1.1 哈希（Hash）`。
   - 每个分类使用独立三列表格：`题目`、`函数作用`、`源码位置`。
   - 函数作用单元格先写实际函数名，再用一句话直接说明作用；复杂度、算法套路和状态不放入表格。
   - 以源码相对路径作为唯一键，更新原行，不重复追加；确认 Wikilink 指向真实文件。
   - 不创建或同步 `.canvas` 副本，不恢复标签维护。

6. **完成验证**
   - 条件允许时使用 C++17、`-Wall -Wextra -Werror` 编译教学版和解除注释后的纯净版。
   - 对修改范围执行最小行为测试，覆盖普通输入、边界输入和题目中的关键反例。
   - 检查看板分类、三列表格、源码链接和题目数量，确认无重复或失效索引。
   - 最终回答先给结论，再说明复盘提炼、源码修改、看板更新和验证结果。

## 边界

- 不因目录分类不完善而批量搬迁无关旧文件；新增分类按需建立。
- 不覆盖用户未授权的无关改动；批量整理时只修改明确纳入范围的题解、看板和 Skill。
- 不把所有标准库函数都收录进复盘，只记录本题使用且具有复用价值的 API。
- Skill 不是后台 Hook；必须依据当前对话触发后执行，不能凭空判定题目已经完成。
