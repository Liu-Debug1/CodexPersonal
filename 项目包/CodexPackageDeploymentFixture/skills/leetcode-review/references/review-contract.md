# 复盘与看板规范

## 单题复盘结构

按当前问题复杂度选用必要部分，不为凑格式重复代码：

1. **正确性结论**：能否通过；若不能，先给最关键的失败原因。
2. **核心思路**：用通俗语言解释突破口和为什么成立。
3. **标准流程**：输入处理、核心循环或递归、终止条件、结果输出。
4. **关键不变量**：循环或数据结构在每一步必须保持什么成立。
5. **复杂度**：时间、额外空间，以及符号含义；只在复盘说明中记录，不写入看板表格。
6. **C++ 知识与 API**：只列本题使用且值得复用的内容，显式写 `std::`。
7. **易错点**：记录错误原因和下次可以自行识别的信号。
8. **可复用模板**：仅在结构可以迁移到其他题目时提供。

## 源码固定结构

每个题解 `.cpp` 按以下顺序组织：

1. 头文件。
2. 教学版 `Solution` 类：函数前有中文 API 注释，函数内部注释解释意图、不变量、边界或风险。
3. 类后的注释调用示例：展示输入、对象创建、函数调用和预期输出；示例不参与编译。
4. 文件末尾的无注释复制版：用一个外层块注释包住完整 `Solution` 类，解除外层注释后可直接复制到 LeetCode。

纯净版必须从教学版复制后只删除注释，不重新设计或修改算法。验证时将纯净版临时解除注释，和教学版分别编译。链表题的纯净类使用 LeetCode 的全局 `ListNode`，本地测试定义放在类外。

## 主分类

源码只放入一个最能代表本题核心矛盾的主分类：

`Array`、`String`、`Hash`、`LinkedList`、`StackQueue`、`Heap`、`Tree`、`Graph`、`BinarySearch`、`Backtracking`、`DynamicProgramming`、`Greedy`、`MathBit`、`SimulationDesign`

看板标题使用中文加英文，例如 `### 1.1 哈希（Hash）`；标题对应源码目录，新增分类时按当前编号顺序继续添加。

## 看板字段

看板在 `## 1.题目索引` 下按算法类型拆分三级标题。每个分类使用独立三列表格：

| 字段 | 填写规则 |
|---|---|
| 题目 | 使用 LeetCode 正式英文名或已确认中文名 |
| 函数作用 | 先写带 `()` 的实际函数名，再用一句话直接说明作用 |
| 源码位置 | 使用相对看板位置的 Obsidian Wikilink |

复杂度、算法套路和复盘状态只在复盘说明或源码注释中保留，不放入看板索引表。

## 幂等更新

1. 将源码相对路径视为唯一键。
2. 更新前先搜索该 Wikilink。
3. 找到时修改原行；找不到时按主分类和题目名插入对应分类表格。
4. 不根据函数名去重，因为不同题目可能使用相同函数名。
5. 保留看板中用户手写的其他章节与备注。
6. 完成后确认每个 Wikilink 指向真实文件，且每个源码只出现一次。
